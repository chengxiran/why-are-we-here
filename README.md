# Why Are We Here?

I am a beginner in programming, VS Code, and GitHub. At first, programming felt like a technical task that belonged to computer scientists rather than artists or designers. In 2026, this feeling is even stronger because AI systems can write working code from a short instruction. If I can ask an AI assistant to make a generative poster, explain an error message, or write a Python script, why should I spend time learning to program myself?

My answer is not that AI will disappear or that artists must compete with machines by writing code faster. AI will probably become more capable, and some programming tasks may become much easier. However, I think learning programming still matters because it changes the way I understand, judge, and control the tools I use. It gives me a more active role in creative work.

## A Small Example: Schotter

My first experience with this idea was the Schotter sketch. The program creates a grid of squares inspired by Georg Nees' 1968 computer artwork. At the top, the squares are ordered. As the image moves downward, the squares become increasingly rotated and displaced. Before using the program, I could simply look at the final image and think of it as an interesting visual effect. However, opening `sketch.py` showed me that the image was created through choices: a seed, a chaos value, numbers of rows and columns, and the size of the canvas.

Changing the `CHAOS` value was a simple action, but it changed how I understood the image. When I increased the value, the lower part of the grid became more unstable and energetic. The program did not decide whether that result was better. It only followed the instructions it was given. I had to look at the output and decide whether the new amount of disorder communicated what I wanted. This is an important difference between generating an image and making an artistic decision.

Using GitHub also made this process clearer to me. When I changed the CHAOS value and saved a new version of the sketch, Git recorded what had changed instead of replacing the old version completely. I could compare the earlier image with the new one and return to an older version if necessary. This showed me that programming is not only about producing a final result. It is also about keeping track of decisions, experiments, and revisions. For creative work, this is useful because an unsuccessful version can still teach me something about what I want to do next.

## From Describing to Specifying

There is a gap between describing an idea and specifying it. I can ask for “an unsettling generative poster,” but that sentence contains many unclear decisions. How much disorder should there be? Should the image feel quiet, violent, mechanical, or playful? What should remain controlled, and what should become random? These are design questions, but programming can help turn them into precise instructions.

This does not mean that programming replaces design. In fact, it makes design judgement more important. Code can produce many variations quickly, but someone still needs to decide which variation is meaningful. The person also needs to understand whether an unexpected result is a mistake, an interesting accident, or evidence that the instructions need to change.

Learning code also means learning a material. A painter learns how paint mixes, dries, and behaves on different surfaces. A photographer learns how light, lenses, and exposure affect an image. In a similar way, a designer who learns programming begins to understand the behaviour and limits of a digital system. The system is no longer a black box. It becomes a material with rules, possibilities, and resistance.

## Authorship and Judgement

The question of authorship becomes more complicated when AI writes code or produces images. I do not think authorship depends only on typing every line of code by hand. Creative work can involve collaboration, tools, accidents, and systems. However, understanding how a system works changes the kind of collaboration possible. If I can read part of the code, change parameters, test alternatives, and explain my choices, then I have more responsibility for the final work.

Ada Lovelace wrote about the Analytical Engine as a machine that could follow operations given to it, rather than a machine that independently creates intentions (Lovelace, 1843). Although technology has changed enormously since then, this distinction is still useful. A system can produce results, but it does not automatically know which results matter to me, my audience, or my project.

For this reason, I do not see programming as only a technical skill. It is a way of thinking through instructions, systems, limits, and choices. AI may make it easier to start, but it does not remove the need for judgement. As a designer or artist, I want to learn enough programming to question the tools I use, rather than only asking them for answers.
